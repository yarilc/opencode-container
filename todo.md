# Remaining sandboxing alignment tasks — OpenCode

Implemented and independently verified on 2026-11-03 against the common sandboxing strategy used by Codex, Claude Code, and Antigravity. All 15 tasks below are complete. Verification passed 19 wrapper tests, 11 real-rootless runtime tests including OpenTUI startup and exit, Bash syntax checks, ShellCheck, and OpenSpec validation. See [acceptance evidence](docs/sandbox-acceptance.md) for coverage and limitations.

## Engine and delegated authority

- [x] **Verify the complete launch-engine contract.** Extend rootless verification to require Linux and a valid `Host.ServiceIsRemote` boolean. Reject named connections, implicit remote contexts, TCP/SSH endpoints, and Unix endpoints without a pathname beyond slash characters. Support local Podman and explicit same-host absolute Unix endpoints. Validate before state-dependent image operations and container startup. Reference: all three baseline launchers.
- [x] **Preserve and validate complete engine responses.** Capture output without discarding additional trailing records and retain query failure status. Reject incomplete/extra fields, invalid booleans, additional blank/nonblank records, and CR characters. Apply equivalent validation to the launch engine and the selected delegation service. Reference: baseline response validation.
- [x] **Make socket delegation an exact, disabled-by-default opt-in.** Replace automatic exposure of any accessible user socket with an explicit switch enabled only by exact value `1`; all other values disable delegation. With delegation disabled, omit the socket mount and explicitly unset session `CONTAINER_HOST`. With delegation enabled, fail before image operations if the selected service cannot be verified instead of warning and silently continuing. Never start the service automatically. Reference: all three baseline launchers. Update AGENTS.md and README, whose current automatic/fallback policy conflicts with this target.
- [x] **Implement verified socket selection and remapping.** Select the first nonempty explicit absolute socket override, Unix launch `CONTAINER_HOST`, then runtime-directory default. Canonicalize and check access to the selected socket, query that exact endpoint, and require rootless `true` plus an absolute reported `Host.RemoteSocket.Path`. Bind the reported host-side source rather than assuming the caller-visible path exists on the engine host. Preserve host absolute workspace/state paths. Reference: all three baseline launchers.
- [x] **Keep host security policy enabled during delegation.** Remove the automatic `--security-opt=label=disable` socket branch. Report SELinux denials and document explicit host policy setup instead of weakening confinement or relabeling host paths automatically. Preserve existing capability dropping and `no-new-privileges`. Reference: the standard-policy behavior of all three baseline launchers.

## State, environment, and mounts

- [x] **Validate private persistent XDG state before image operations.** Privately create, physically resolve, and validate each writable OpenCode config/data/cache/state directory: caller ownership, required read/write/traverse access, and no group/other permissions. Use a scoped creation umask and reject insecure existing paths without automatic chmod/chown or credential copying. Ensure mount destinations and the entrypoint's effective HOME/XDG paths remain consistent, including nonstandard host homes. Reference: baseline persistent-state validation; retain OpenCode's XDG layout and per-user image identity.
- [x] **Provision temporary filesystems explicitly.** Add `--read-only-tmpfs=false` and explicitly define all required temporary paths, including `/run` and `/var/tmp`, with capacities, `nosuid,nodev`, and access modes for the mapped user. Retain executable `/tmp`, because OpenTUI extracts and loads a shared library there. Verify effective mount flags and ephemeral lifetime. Reference: baseline explicit provisioning; identical sizes or execution policies are not required.
- [x] **Forward allowed credentials by name only.** Keep the explicit environment allowlist, but use `--env VARIABLE` rather than `--env VARIABLE=value` so keys and passwords are absent from wrapper process arguments. Retain deliberate nonsecret path/identity assignments and prevent forwarded/default environment settings from overriding disabled delegation. Reference: Antigravity's API-key forwarding and Pi's existing by-name forwarding. Do not claim this hides values from container processes or engine inspection.
- [x] **Support physical bind paths containing commas.** Replace the current unescaped comma-delimited `--mount` construction with a safely encoded bind representation for workspace, XDG, optional read-only, and socket paths. Preserve physical absolute sources and the original working directory. Reference: baseline quoted bind arguments support commas and spaces; retain OpenCode's deliberate optional read-only integrations.

## Container and image lifecycle

- [x] **Complete bounded name reservation and error handling.** Keep atomic `create`, but enumerate running/stopped names through a checked command, use bounded base-ten suffix parsing including `08`, and cap retries at 20 confirmed collisions. Separate stdout container identity from stderr diagnostics and preserve actual creation failures, including 125. Never replace or remove existing containers to reserve a name. Reference: baseline naming/lifecycle handling.
- [x] **Implement bounded signal forwarding and owned cleanup.** Replace the shared `trap cleanup EXIT HUP INT TERM` with explicit interruption handling and EXIT cleanup. Track the full owned ID via private creation records and track create/attach clients. Forward TERM/INT/HUP, preserve interruption statuses 143/130/129 and application exit codes including 125, bound control calls/graceful waits/client reaping, and reconcile interrupted creation within a finite budget. Clean up only verified owned IDs and report unresolved outcomes. Reference: baseline session lifecycle.
- [x] **Keep stdin open independently of TTY allocation.** Add interactive stdin support even for pipes/files; allocate a TTY only when both stdin and stdout are terminals. Preserve attached stdin and EOF when introducing background-client lifecycle handling. Reference: baseline `--interactive` plus conditional `--tty`; OpenCode currently sets both only for terminal sessions.
- [x] **Reject unexpected image-inspection failures.** Build automatically only when `podman image exists` reports missing-image status 1; stop on other engine/storage errors rather than treating every failure as a missing image. Retain version/username/UID/GID image tags and the pinned OpenCode default. Reference: all three baseline launchers.
- [x] **Add explicit wrapper build, shell, and worktree modes.** Provide equivalents of `--container-build`, `--container-shell`, and `--container-git-worktree`, plus side-effect-free wrapper help. Parent mounting must be explicit and preserve the original physical workdir; shell mode must bypass the OpenCode entrypoint and omit agent arguments. Keep ordinary OpenCode arguments unchanged and apply the same preflights to all modes. Reference: shared baseline wrapper modes.
- [x] **Deny build-context inputs unless explicitly allowed.** Replace the current `.dockerignore` blacklist with a default-deny policy supported by the Podman build, explicitly allowing the root Dockerfile, `opencode-entrypoint`, and the chosen ignore file. Verify that required COPY inputs work while unknown/nested files and local state/credentials remain excluded. Reference: baseline default-deny build contexts, including Antigravity's explicit helper allowlist.
